## 1. 新增句子並顯示

- [x] 1.1 寫失敗的檢查: 在頁面尾端建立 `?selftest` 檢查區塊, 加入第一組 assert - 送出的內容去頭尾空白後附加到陣列最後, 去空白後為空字串則陣列不變 (Scenario: 送出有內容的句子, 送出空白內容)
- [x] 1.2 實作到 assert 通過: 把現有 textarea 換成 form 內的單行 input 加新增鈕, 建立句子陣列與不碰 DOM 的新增純函式, 寫 render 函式依序畫出每一項 (清單為空時顯示提示文字), 送出後清空輸入框
- [x] 1.3 驗收: 開 `?selftest` 確認全綠; 一般頁面依序加入三句, 確認由上而下依加入順序顯示, 每次送出後輸入框清空, 只輸入空白送出時清單不變, 送出重複句子會多出獨立的一項 (Scenario: 送出重複的句子, 清單有內容, 清單為空)

## 2. 清單本機保存

- [x] 2.1 寫失敗的檢查: assert 還原函式 - 收到正常的 JSON 陣列字串時回傳原順序, 收到 null 或無法解析的字串時回傳空陣列 (Scenario: 首次使用, 本機保存的資料無法解析)
- [x] 2.2 實作到 assert 通過: 用單一 key 讀寫清單, 讓所有清單變動經過同一個寫回點, 啟動時先還原再 render
- [x] 2.3 驗收: 加入數句後重新整理, 清單內容與順序不變; 手動把本機儲存的清單值改成無法解析的字串後重新整理, 頁面所有功能仍可用且清單為空 (Scenario: 重新整理後清單還在)

## 3. 單句播放

- [x] 3.1 先確立紅燈: 記下驗收步驟「按下清單中第二句的播放鈕應只唸該句」, 確認目前清單項目上根本沒有播放鈕, 這一步必然失敗 (本 slice 的行為在語音合成層, 依 design.md D8 不做自動化斷言)
- [x] 3.2 實作: 每個清單項目右側加播放鈕, 在清單容器上用事件委派依索引取句子, 播放前先取消目前朗讀, 沿用現有取得音色與語速的方式建立朗讀
- [x] 3.3 驗收: 按第二句的播放鈕只唸第二句且不續唸下一句; 唸到一半按另一句的播放鈕會立刻中斷改唸新的一句; 把語速調成 0.5x 後再按確認變慢; 重新整理後音色與語速維持上次選擇 (Scenario: 播放單一句子, 播放期間再按其他句子, 調整語速後播放, 重新整理後設定保留)

## 4. 單句刪除與二次確認

- [x] 4.1 寫失敗的檢查: assert 依索引刪除的純函式 - 只移除指定索引那一項, 其餘句子的內容與相對順序不變 (Scenario: 確認刪除中間的句子)
- [x] 4.2 實作到 assert 通過: 每個清單項目加刪除鈕並走同一個事件委派, 在動資料之前呼叫原生 confirm, 使用者取消時直接結束不做任何變更
- [x] 4.3 驗收: 三句時刪除中間那句並確認, 剩下兩句內容與順序正確; 同樣操作但在 dialog 選取消, 清單完全不變; 刪除後重新整理確認變更有被保存 (Scenario: 確認刪除中間的句子, 取消單句刪除)

## 5. 清空全部與二次確認

- [x] 5.1 寫失敗的檢查: 在瀏覽器這一層確立紅燈 - 清空鈕存在, 有句子時可用, 空清單時停用且按下不跳 dialog, 取消不變更, 確認才清空 (Scenario: 確認清空, 清單為空時的清空鈕). 原本寫的是「assert 清空後為空陣列與停用條件」, 但那兩者在程式碼裡就是 `[]` 與 `!list.length`, 為了可被 assert 而包成純函式只會做出唯一用途是被測試的 Middle Man, 因此改在行為層驗
- [x] 5.2 實作到 assert 通過: 加入清空鈕, 動資料前呼叫原生 confirm, 清單為空時把按鈕設為停用
- [x] 5.3 驗收: 多句時清空並確認, 清單變空並顯示空清單提示; 同樣操作但選取消, 所有句子保留; 清單為空時清空鈕為停用且按下不會跳出 dialog (Scenario: 確認清空, 取消清空全部, 清單為空時的清空鈕)

## 6. 依序播放全部

- [x] 6.1 寫失敗的檢查: assert design.md D6 的續播判斷 - 播放序號未變時該結束事件可以續播, 中止使序號遞增後帶著舊序號的結束事件不得續播 (Scenario: 依序播放中再按一次)
- [x] 6.2 實作到 assert 通過: 在輸入區與清單之間加依序播放鈕, 用朗讀結束事件串接下一句並以播放序號守住續播, 播放中再按一次即中止, 清單為空時停用, 刪除與清空在變更資料時一併中止播放
- [x] 6.3 驗收: 三句依序唸完後停下且按鈕回到可再次播放的狀態; 唸第二句時再按一次, 立刻停止且第三句不會被唸出; 播放中確認刪除某句或清空, 朗讀立刻停止; 清單為空時依序播放鈕為停用 (Scenario: 依序播放走完佇列, 清單為空時的依序播放, 依序播放中再按一次, 依序播放中變更清單)

## 7. 句子選取與維護

- [x] 7.1 寫失敗的檢查: assert 選取索引的重映射純函式 - 刪除某個索引後, 該索引從選取移除, 大於它的索引各往前搬一格, 其餘不變; 以及還原時丟掉超出清單長度的選取索引 (Scenario: 刪除句子後選取仍對應原本的句子, 刪除被勾選的句子, 保存的選取超出目前清單長度)
- [x] 7.2 實作到 assert 通過: 每個清單項目加勾選控制, 選取存成 JS 的索引集合並由 render 決定每一項的勾選與否 (不從 DOM 讀), 刪除路徑呼叫重映射, 清空時選取一併歸零, 選取變動與句子走同一個寫回點存進第二個 key, 啟動時還原並過濾超出範圍的索引
- [x] 7.3 驗收: 勾選第一與第三句後新增一句, 原本兩句仍勾選且新句未勾選; 刪除第二句後仍是原本那兩句被勾選; 刪除被勾選的第三句, 第一句仍勾選; 清空後沒有任何勾選; 勾選後重新整理, 勾選還在; 手動把本機儲存的選取改成超出清單長度的值後重新整理, 頁面正常且超出的部分消失 (Scenario: 勾選與取消勾選, 新增句子不影響既有選取, 清空全部後選取一併清空, 重新整理後清單與勾選都還在)
